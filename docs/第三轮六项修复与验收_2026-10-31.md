# 第三轮六项：修复、保护与验收

日期：2026年10月31日。开工基准98ae0d9，功能基准a8c5fb2；原始失败证据保留在audit3目录。本轮按用户“逐个修复”处理3项新缺陷及3项已知边界。没有安装新依赖、接入云推理或扩展无关前端。

当前版本local-ai-prototype-5，分析版本6。三个新缺陷已修；转场样例通过更密取样和服务器风险拦截处理；多短片段已支持连续旁白；HDR采用明确识别/拒绝并提示先转SDR，**没有自动HDR色彩转换**。这是明确的范围处理，不能宣传为支持HDR成片或任意素材零漏检。

## 实现与关键取舍

### 字幕与事实

`text_rules.py`提供统一的显示文本规则，`caption_for`将允许的换行/制表符作为空格处理，事实原值与商品绑定仍保留原文。方案验证使用同一文字，`write_ass`再做防御处理，避免CR在字幕事件中提前终止。原花括号/反斜杠安全显示保留；没有通过删除型号或优惠条件获得通过。

### 上传

上传循环逐文件收集结果，坏文件或过大文件不会让后续文件消失。重试对本机文件计算SHA256，结合文件名/大小识别同一文件；仅在对应素材仍在当前项目且可访问时跳过。计算哈希与素材处理均在本机，增加少量读文件/内存开销，没有上传第三方。当前没有新加队列取消、云上传或自动文件清理功能。

### 保存与恢复

`session_store.py`把有效方案和编排方式放入saved_edit，并记录事实、源身份、用途、确认和分析版本的上下文哈希。导入/重开时先reconcile再preflight，检查哈希与当前条件；改商品、改源、确认失效后不会载入旧可生成方案。上下文哈希防止意外沿用旧决定，不是对商户事实真实性的认证。

API仍返回平铺project，兼容旧的仅素材/事实项目。保存采用临时文件替换；无可用方案时明确只保存素材与事实。JSON导出内容也由服务器核验打包，实际API导出→导入往返通过；本轮没有声称内置浏览器的下载传输已验收。交付目录提供可直接导入的项目JSON。

### 语义风险

分析版本升级到6，旧确认需要重新核对。语义证据从原5帧扩至边界及每0.5秒，仍基于12fps代理，绝非逐帧语义核验。T02实测0.025、0.5、1.0……2.5……7.94秒共19帧，18帧给商品、1帧给人物风险；不是整体均值足够高就放行。

`review_store.py`把风险结果绑定源哈希、镜头身份、模型权重、分析版本与策略版本；确认与渲染读服务器记录，项目JSON不能把风险清空后绕过。缓存只复用相同证据/策略的候选，不自动恢复确认；后续修改风险规则要升级POLICY，不能沿用旧结论。

风险判定结合模型类别变化、RGB差异与亮度归一化后的画面结构相关性，避免把同一画面的曝光淡入直接当成异物。正常淡入+实际AI对照通过。数值仍是本机启发式，不是校准的概率，可能误拦/漏检；更短混入、模型错判、从未运行AI而人工误确认仍需完整播放复核。当前不自动修剪语义混入区间，也不接受一个普通勾选覆盖已发现的风险；应提供安全区间/重新上传或换可用素材。

### 跨短镜头的连续旁白

原单镜头DP优先；只有其无法形成完整可行方案时，`grouped_planner.py`对受限候选做组合搜索。每角色最多4个源，组最多16秒，全片最多10个实际片段，每个源片段1—8秒，全片预计不超过45秒。候选数量受限，不能称为全局最优算法。

旁白组的clips保存每个源的编号和范围。校验逐源检查用途、商品绑定、质量、风险、越界及重复；渲染先拼接画面，再为整个组生成一次旁白和字幕。组保存完整所选画面，报告visual_clips给出源范围及输出时间映射。网页以组为单位重排，组内不独立重排；原声、音乐及动作语义完整性仍未实现。

实测商品组输出区间2.606—6.606秒，共4秒；前2秒与后2秒来自不同源，两个抽帧已查看；商品文案只出现在一个旁白时段。程序时序证明只生成一次，真人自然度/停顿仍需用户听看。两幅样片之一为镜像变体，仅用于辨别剪辑来源，不是商品展示建议。

### HDR

本轮选择可验证的明确边界：检测smpte2084/arib-std-b67时不给出偏色成片，提示先转SDR。原视频保留，其他正常文件继续。旧HDR分析升级失败会显示该具体原因，避免反复要求无效重传。用户成本是多一次素材转换；自动色调映射、HDR显示设备与手机实拍校准留待专项验证，不能把本轮写成支持自动HDR→SDR。

## 使用与交付

本机网址 http://127.0.0.1:4180/ ，已保留新的跨镜头预览页。文件在“交付/第三轮六项修复版”：模拟技术样片、运行报告、可恢复顺序的项目JSON和本文。导入JSON会重新核对当前本机源；换电脑仍需原素材与重新确认，JSON没有携带原视频。

旧项目首次载入会升级分析并撤销旧镜头确认，事实保留。先完整查看视频，确认用途和商品对应，再编排/保存。短素材不必重复填写文案；提供同一商品的两段已确认片段，系统在需要时组成一个旁白组，检查页面的片段数和时长即可。

可复现命令（主服务4180需在线）：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests
.\.venv\Scripts\python.exe -u -X utf8 verify_third_audit_fixes.py
.\.venv\Scripts\python.exe -u -X utf8 verify_audit_fixes.py --out evidence/fixes3-2026-10-31/prior-audit-regression
.\.venv\Scripts\python.exe -u -X utf8 verify_second_audit_fixes.py --out evidence/fixes3-2026-10-31/second-audit-regression
```

第三轮脚本支持`--only T02_semantic`等单项；会新增测试素材/视频并更新当前验证结果，原始audit3证据不动。网页流程需另行验证；保存测试必须先备份并恢复。finalize_third_fixes_20261031.py绑定本次最终网页任务ID，用于本次交付收集，不是通用成片入口。

本轮完成的是对应技术场景与明确的保护行为。真实商户正确率、人工总耗时、真人听感、手机/跨电脑、任意混剪的语义零漏检均未验收；由用户继续看听当前版本，再用获授权的一店一商品素材做真实验证。
