# 邻镜智作协作开发指南

当前基线：2026年11月2日。提交前完整程序测试146项通过，饭店首页已有桌面／手机网页流程验证。真人拍摄、实拍示例、商户使用和宣传效果仍待验收。

## 先拿到代码

```powershell
git clone https://github.com/zuimo3456/linjing-zhizuo.git
cd linjing-zhizuo
```

先读 `AGENTS.md`、`PROJECT_STATE.md` 和本指南。状态文档中的本机端口、路径、进程号、已生成视频只描述原开发电脑，克隆后不会自动存在。

## 只做前端：先不下载模型

安装Python 3.12后，在项目目录运行：

```powershell
python -X utf8 server.py
```

打开 http://127.0.0.1:4180/ 。不安装模型即可修改和查看首页、筛选、拍摄清单与工作台表单。此模式不能代替素材处理、AI分析或视频生成验证；页面会提示未配置的模型。端口已被占用时，先检查是否已有本项目服务。

主要页面文件：

| 文件 | 职责 |
| --- | --- |
| `static/index.html` | 首页、拍摄清单、工作台和研究页面结构 |
| `static/style.css` | 页面样式、响应式布局 |
| `static/app.js` | 首页选择与路由、拍摄任务、工作台交互及接口调用 |
| `server.py` | 本地HTTP服务与API入口 |

三类首页目标映射现有后端：推荐一道菜→`attract`，推广套餐→`promo`，介绍饭店→`visit`。`creative_brief`描述创作意图，不能用它自动确认商品、事实或素材。

## 需要处理视频时

Windows下安装Python 3.12或uv、FFmpeg及ffprobe，确认它们在PATH中。当前比例处理要求FFmpeg支持 `scale=...:reset_sar=1`，已验证版本为8.1.1。

有uv时运行 `start.ps1`，它会创建 `.venv` 并安装 `requirements.txt`；也可以手动安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -X utf8 server.py
```

本地视觉候选分析另外执行 `setup-local-ai.ps1`；本地Vivian配音另外执行 `安装开源女声.ps1`。配音需要独立环境、约4.5GB模型和合适的CUDA显卡；原机为8GB RTX4060，其他硬件尚未验收。完整细节见 `docs/开源活泼女声接入_2026-11-02.md`。

模型、虚拟环境、上传视频和已生成视频不会随Git克隆。项目JSON也不包含原素材；跨电脑验证应自行准备获得授权的素材。

## 每个人使用自己的分支

有仓库写权限的同学，在开始修改前：

```powershell
git switch main
git pull --ff-only
git switch -c feature/你的功能名
```

完成后先查看自己改了哪些文件，再提交并推送分支：

```powershell
git status
git add 具体文件路径
git commit -m "说明具体改动"
git push -u origin HEAD
```

然后在GitHub提交Pull Request，经另一位同学检查后合入main。没有写权限时，可以先Fork仓库，向自己的Fork推送分支，再向原仓库提交Pull Request；要直接推送原仓库分支，需要仓库所有者添加协作者。

尽量按首页与拍摄提示、素材检测、剪辑规则、配音等职责拆分任务。修改共享的 `static/app.js`、`planner.py` 或 `PROJECT_STATE.md` 前先在团队内协调；不要覆盖其他人的未提交改动，也不要强制推送main。

## 合入前检查

视频开发环境安装好后运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

修改前端后，还应实际检查筛选、返回、刷新、手机布局和工作台信息带入。已有 `verify_restaurant_home_browser.py` 是原机集成验证脚本，需要独立Playwright环境、Edge、4193测试服务和本地保存项目；不能直接当作刚克隆仓库的零配置测试。

每个PR说明改动目的、验证结果及未完成部分。事实校验、商品对应和完整优惠条件不能因演示需要而绕过。

## 哪些内容留在本地

`.gitignore`排除了 `.venv/`、`.tts-venv/`、`.models/`、`data/`、`交付/`、环境密钥文件及新产生的日期实验目录。日期实验目录可能包含项目备份、第三方画面、原机路径和模型运行副本，保留在本地；需要共享时单独检查和整理。

历史已跟踪的技术验收记录仍保留。报告中引用的本地视频、模型和新实验输出不一定在仓库里。团队自行录制的公开示例应确认可分享后放入专门的示例目录，再明确添加到Git。
