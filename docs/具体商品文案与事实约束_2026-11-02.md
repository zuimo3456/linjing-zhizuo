# 门店、具体商品与特点文案

日期：2026年11月2日。用户指出不同门店需要不同文案，例如写出具体咖啡名称。本轮已把文案与已确认店名、具体商品名、可选商品特点关联，仍采用本地受约束模板，不是任意自由写稿或凭画面识别真实菜单。

## 使用方法

在事实卡中填写“具体商品名称”，例如菜单上确实存在的“生椰拿铁”，而不是只写“咖啡”。填写来源并确认；然后填写可选的“商品特点”，例如已经核实的“使用椰乳”，填写来源并确认。商品镜头仍需单独确认确实对应这款商品，最后重新生成方案和视频。当前预览`http://127.0.0.1:4191/`，刷新即可读取新页面。

仅写“咖啡”等大类时会给出补充具体名称的提示，仍允许使用已确认的大类，不自动猜测拿铁、美式或产地。未填写特点不影响正常使用；未确认的特点不会进入文案。没有来源的“招牌、现磨、低糖、低卡、销量第一”等不会被模板补入。价格、优惠限制和有效期继续保留完整确认文本。

## 防止串用商品信息

可选事实类型`product_detail`使用`product_ref={id,value}`关联已确认商品；服务器同时验证来源、事实确认和对应名称。改名或取消商品确认后，网页立即撤销特点确认；原有商品画面对应也按原规则失效。导入带旧特点的改名项目时，保留原特点文字和来源，取消其确认并显示提示，不直接套用到新商品。重新核对并确认后提示会消失。

`caption_for`生成的具体文字和事实引用必须与服务器计算完全一致；篡改方案追加“全城第一”等不会通过。新文字会由Vivian重新合成测时，仍受语速、画面、确认、语义风险和当前15–30秒时长规则约束；不删必要优惠条件、不借用其他商品画面来放下长文案。特点过长时需缩短非必要信息或提供合适素材。
