## 打开与体验

本轮新女声验证预览地址为 http://127.0.0.1:4191 ，原4180服务在其他工作中使用，未将其停止。常规启动地址仍为 http://127.0.0.1:4180 ：双击“启动邻镜智作.cmd”后打开。旧服务需要重新启动才会加载新配音代码，请勿同时启动两个服务争用同一端口。

第一次在其他电脑运行：需要Windows、Python 3.12或uv、FFmpeg和ffprobe、Microsoft YaHei字体及支持CUDA的NVIDIA显卡（本轮为8GB RTX4060）。start.ps1会创建独立视频环境并安装requirements.txt；另外运行“安装开源女声.ps1”安装独立配音环境和约4.5GB官方模型，当前电脑均已就绪。配音采用Apache-2.0的Qwen3-TTS 1.7B / Vivian预置中文女声及轻快指令，不需要克隆他人的声音；推理完全本地运行。Linux/macOS、CPU降级和低显存配置尚未验收。

换声后请重新点击“生成可检查的方案”，再生成视频。旧视频声音不会自动变化；旧方案会要求重测旁白，已确认事实和素材保留。首次新文案需要加载模型和合成，重复文案会直接复用缓存；模型空闲两分钟自动释放显存。

当前验证的FFmpeg为8.1.1，视频比例处理使用scale的reset_sar选项，其他电脑需要包含该选项的版本。上传后会生成本地H.264复核副本，原视频保留不变，因此额外占用转码时间和磁盘空间。

1. 点击“体验模拟案例”。四段原创插画测试片会载入，并明确显示“模拟案例”。
2. 可点击“本地 AI 分析素材”，检查多时刻候选；不确定会暂不判断，所有镜头需重新确认。模拟插画不是模型评测集，模型可能弃权。
3. 查看各镜头的视频并确认用途；商品还需确认“画面商品确实是…”。点击“生成可检查的方案”，检查顺序与事实引用。
4. 删掉地址、修改商品名称或取消镜头确认，再生成，查看阻止生成和补拍提示。
5. 恢复样本，确认方案并生成视频。等待页面结果，播放，下载MP4、运行报告和证据包。
6. 点击“研究与验证”，查看程序用例和真实实验的区别；人工复核记录可导出CSV。

新项目应点击“开始真实项目”，上传获授权的视频，填写事实和来源，检查抽帧并确认镜头标签，再编排。上传真实素材会退出模拟项目，避免混入模拟事实。导入项目JSON不包含原始视频；跨电脑使用时仍需准备原素材。

损坏/失效素材不会拖累其他素材的AI分析，页面会列出成功、失败和跳过数量；“成功”表示完成候选分析，不代表判断正确。淡入等素材会列出可用与不可用区间；只确认实际查看的可用区间。旧版项目升级后需重新核对用途与商品对应，再保存项目。模型状态区分文件已校验和实际已加载，异常时可先手工标注。

批量上传按文件列出成功/失败，坏文件之后仍会继续；同名同内容的成功文件重试会跳过。从模拟项目上传时，首段分析成功后才开始真实项目，整批失败保留原事实、镜头、方案与预览。项目保存现在包含有效剪辑方案和顺序，重开或导入时重新核验，事实、素材或确认改变会使旧方案失效。导出内容也包含该记录，但浏览器下载本身仍需用户验证。

素材语义证据增加到边界及每0.5秒；出现明显画面结构切换且模型给出无关/人物风险时，会标出时刻并阻止直接确认，风险与原片绑定。它仍可能漏掉更短内容或模型误判，须完整播放复核。HDR（PQ/HLG）当前明确要求先转普通SDR / BT.709再上传，尚未实现自动HDR色彩转换。

当单镜头放不下旁白时，可组合2—4个同用途且分别确认的片段，包括恰好8秒的素材，让同一段旁白只播放一次。每个实际片段1—8秒、每组最多16秒、全片最多10实际片段且预计不超过45秒；组内每段商品也必须分别确认。组合不足时，提示会计入实际末段引导语并显示画面合计时长。默认优先原单镜头编排，组合降级是有界搜索，不承诺全局最优；原声与音乐仍未实现。复制文字中的CR/LF/Tab/U+2028/U+2029在旁白和字幕中统一显示为空格，原始事实保留。

组合搜索可以跳过中间片段，每类最多12个候选、2—4片成组，最多100000次候选分配；达到搜索上限会说明限制，不把搜索未找到等同于一定需要补拍。隐藏方向控制字符不能直接确认或生成；旧项目会保留原文、显示[U+…]标记并取消该事实确认，需要重新填写可见文字。

素材分析版本7区分原片与复核视频时刻，网页在有偏移时同时列出两段区间。视频轨和音轨起点不同、整体时间戳平移、晚到音轨均有专项回验。旧项目升级会保留事实、撤销旧素材确认及旧方案，请完整查看后重新确认并保存；同证据已有语义风险不会因升级被清掉。

## 已实现与限制

已实现：多文件上传、完整镜头覆盖与短切检测、独立画面质量拦截、边界及中间取样、本地用途候选及弃权、完整视频复核、关联原文件/镜头范围的签名确认、商品对应确认、事实和促销有效期检查、三类目标、真实配音时长预检与可行镜头分配、受限文案组合、缺失提示、离线配音字幕、预览下载、项目保存、失效镜头移除、运行证据及约束回归。处理等待期间锁定编辑，并检查结果是否对应当前项目版本。

待验证：真实视频中的用途候选可靠性、人工修订成本、手机与跨电脑操作、真实商户试用。当前只支持720×1280画外音路径；原声、逐字对齐等不属于本轮完成项。字幕按实际短句语音测时；配音最多1.18倍速，编排前检查是否放得下，不长时间停帧。每段最多使用8秒素材；制作过程保留已选择的完整区间。完整长优惠条款可能无法放入当前结构，需要另行拆分结构，不能删掉必要条件来强行通过。旧项目升级会保留事实并要求重新确认素材；换电脑也需重新确认。

本地AI在当前电脑已装好。在另一台Windows电脑安装，执行 `powershell -NoProfile -File .\setup-local-ai.ps1`；下载约191MB固定版本权重（支持分块复用），运行时不联网推理。模型文件不入Git。requirements-local-lock.txt保存当前本地AI环境的完整版本。

默认全部本地运行，无付费API调用。视觉API适配器是未联调的可选能力，不会因为电脑已有其他密钥而自动调用。它只在显式设置LINJING_VISION_API_URL、LINJING_VISION_API_KEY、LINJING_VISION_MODEL并执行带--send-frames的命令时，发送选定抽帧到配置的供应商；不发送店铺事实卡。调用前应核对授权和预算。

服务仅监听127.0.0.1，适用于本机开发，不是公开生产服务。不要直接改成公网监听。素材在data/，默认不上传云端、不入Git，目前没有自动清理机制；人工备份与删除应核对项目后操作。当前任务队列只存内存，服务重启会丢失任务状态，已生成文件仍在data/。

## 如何理解核心算法

以到店目标为例，有门头、商品、环境三个角色；每个镜头可以支持一个或多个角色。相同镜头只分配一次，优先填满三个角色，再提高质量与可用时长。用三个二进制位表示角色是否已覆盖，共8种状态，依次考虑各镜头即可完成分配。这里的状态转移与C++动态规划练习相通。

分配之前，先测量每种受限文案的实际配音；时长不够的候选不进入对应角色的选择。按原素材顺序编排时，也要检查最后一段通用引导语能否放下。质量高不能补偿旁白放不下的问题。

例子：镜头A同时可作门头和商品，质量高；镜头B只能作门头，镜头C只能作环境。逐个贪心先把A用作门头会缺商品；全局分配选择B作门头、A作商品、C作环境。tests/test_invariants.py有此用例。算法不能检验标签是否看错，因此需要独立评价模型标签与人工确认成本。
